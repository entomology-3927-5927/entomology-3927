Creating visualizations in R: the tools available

There are a myriad of ways to create data visualizations in R. Indeed, a bunch of built-in tools already exist within base R to create plots, and many folks use these tools exclusively to create plots for their presentations, manuscripts, and websites. And the plots from base R…do the job…but aren’t particularly aesthetic!

One of the most important qualities of good data visualizations is that, in addition to being truthful and functional, they are beautiful. This means being cognizant about basic design and color theory and chosing the plots carefully and considerately to best serve the purpose of communicating the data. Here, the Great British Baking Show addage of “Style and Substance” comes into play. It’s possible to create incredibly data-rich plots that are truthful and functional, but you also should want to look at it – and looking at it shoudl convey an emotional response in addition to an analytical response. On the flip side, it’s possible to create a plot that is stunningly beautiful, but lacks sufficient data and analytical substance. Walking that balance is what data visualization is all about.

To accomplish this, we’ll almost exclusively be using the ggplot2 package in the Tidyverse. It’s the most flexible and well-equipped library for creating just about any sort of data visualization, and is designed to work with tidy data and the various packages that produce tidy data. In addition, many, many packages create plots that are ggplot2 objects, meaning that we can take and modify them to match a particular aesthetic, add additional information, or combine them with other plots. There’s also an abundance of code and tutorials out there to create ggplot plots.

Anatomy of a plot

ggplot plots (or objects, as we’ll be referring to them) are composed of various layers that, together, work to build a plot.

library(tidyverse)

# Data + Mapping
ggplot(data = mpg, mapping = aes(x = cty, y = hwy)) +

  # Layers
  geom_point(aes(color = displ)) +
  geom_smooth(method = "lm") +

  # Scales
  scale_color_viridis_c() +

  # Facets
  facet_grid(year ~ drv) +

  # Coordinates
  coord_fixed() +

  # Theme
  theme_minimal()
Component Purpose Common functions
Data The dataset used to create the visualization. ggplot(data = ...)
Mapping Maps variables in the dataset to visual properties (aesthetics). aes()
Layers Determines how data are visually represented, including geometry, statistical transformations, and position adjustments. geom_point(), geom_line(), geom_bar(), geom_smooth(), geom_histogram()
Scales Controls how aesthetic mappings are translated into visual properties, including axis limits, breaks, labels, and colors. scale_x_*(), scale_y_*(), scale_color_*(), scale_fill_*()
Facets Splits data into multiple panels based on one or more categorical variables. facet_wrap(), facet_grid()
Coordinates Controls the coordinate system and how spatial positions are displayed. coord_cartesian(), coord_fixed(), coord_flip(), coord_polar()
Theme Controls non-data visual elements, including backgrounds, gridlines, text, axes, and legends. theme(), theme_minimal(), theme_classic(), theme_bw()
  • Mapping (aes()) tells ggplot2 what variables to visualize.
  • Layers (geom_*()) tell ggplot2 how to visualize those variables.
  • Scales (scale_*()) tell ggplot2 how to translate those variables into visual properties.
  • Themes (theme_*()) control how the overall plot looks/the aesthetic (text, lineweight, etc.)

Mapping

Mapping connects variables on our dataset to the visual properties of a plot. They’re defined using the mapping = argument in ggplot and the various layers of our plot. They quite literally map the connection between data and plot. When we map variables to our plot aesthetics, we have two options: using (1) global aesthetics or (2) layer-specific aesthetics.

  • Global aesthetics are defined inside ggplot(mapping = aes()) and are inherited by every layer in the plot.

  • Layer-specific aesthetics are defined inside an individual geom_*() and apply only to that particular layer. There are many different aesthetic mappings in ggplot, and I describe the primary ones in the table below (there are several more specific to different layers):

Aesthetic What it controls Example
x Horizontal position aes(x = temperature)
y Vertical position aes(y = abundance)
color Color of points, lines, and outlines aes(color = species)
fill Interior color of shapes and polygons aes(fill = habitat)
size Size of points and text aes(size = abundance)
shape Shape of points aes(shape = species)
alpha Transparency / opacity aes(alpha = abundance)
linetype Line style (solid, dashed, dotted) aes(linetype = treatment)
linewidth Width of lines aes(linewidth = abundance)
group Groups observations for statistical or geometric operations aes(group = site)
label Text labels displayed on the plot aes(label = species)
Tip

Anytime we’re mapping a variable to a plot element, we use the mapping = aes() argument. If we are setting a fixed element of a plot (e.g., making all points a certain color, or a certain shape/size, those settings are controlled using the same aesthetics, but set OUTSIDE the mapping = aes() argument. For example:

# Mapping species to point color
ggplot(
  data = my_data,
  mapping = aes(x = x, y = y, color = species)
) +
  geom_point()

# Setting point color "black" to color
ggplot(
  data = my_data,
  mapping = aes(x = x, y = y),
  color = "black"
) +
  geom_point()

Layers

Layers are the actual bits and bobs that together compose our plot – things like geometries (e.g., lines, points, polygons, rectangles) and the other sets of instructions about how to actually construct it (i.e., mappings, positions, statistical transformations). Typically, we define all of these various components in our within geometries, or geoms:

ggplot(data = <DATA>) + 
  <GEOM_FUNCTION>(
     mapping = aes(<MAPPINGS>),
     stat = <STAT>, 
     position = <POSITION>
  ) +
  <COORDINATE_FUNCTION> +
  <FACET_FUNCTION>

There are many, many geometries that we can utilize in ggplot to create our plots, and I recommend you take a look at your ggplot2 cheatsheets to see most of them. There are also many add-on packages that add additional, specialty geoms that you can use to build your plots. I encourage you to search for those on your own time, as their use is beyond the scope of this course.

geom_point() Individual points Scatterplots
geom_line() Lines connecting observations Time series, trends
geom_path() Lines connecting observations in data order Trajectories, movement paths
geom_smooth() Fitted trend line with confidence interval Relationships, regression
geom_bar() Bar heights based on counts Categorical frequencies
geom_col() Bars with heights based on supplied values Summarized data
geom_histogram() Frequency distribution of continuous data Distributions
geom_density() Smoothed density distribution Distributions
geom_boxplot() Median, quartiles, and outliers Comparing distributions
geom_violin() Distribution density by group Comparing distributions
geom_jitter() Points with added positional variation Reducing overplotting
geom_errorbar() Error bars around estimates Uncertainty, confidence intervals

geom_text() Text labels Annotating observations

Important

The order of your geom layers matters! They will be drawn onto the plot from top, to bottom. In our example above, this means that the geom_smooth() layer will be drawn on top of our geom_point() layer.

Scales

Scales are the settings that translate your data into actual visible aesthetic layers (i.e., geoms) in ggplot. They control the axes, the color gradients of continuous variables, the color palette of categorical variables, etc. Most of the time, we modify these plot settings by appending a scale_* function to our ggplot object. There are a couple of primary scales that we need to be concerned with:

  • Position scales and axes: used to control the locations of visual entities in a plot, and how those locations are mapped to data values.
  • Color scales and legends: used to control the color/appearance of visual entities in a plot.

Position scales and axes

Most of the time, we use numeric position scales to position our plot objects, typically using scale_x_continuous() or scale_y_continuous() which map data linearly. A few other options exist, including for reversing scales (scale_x_reverse()) or transforming from linear to logarithmic (scale_x_log10()).

Within the scale_*_continuous() functions, we can adjust a variety of arguments to change the appearance of our x and y axes:

  1. limits: change the range of values covered on the axes
  2. transform: add a mathematical transformation to the scale of values (e.g., log, ln, sqrt)
  3. breaks/minor_breaks/n.breaks: adjusts the position of the axes’ tick marks
  4. labels: adjust the label of the axes’ tick marks (every break is associated with a label)
Tip

All of these functions are defined and their use documented in the help documentation of scale_*_continuous() functions (e.g., ?scale_y_continuous()).

Color scales and legends

We use color in a variety of different ways to distinguish different categorical groupings (e.g., treatment, species), or continuous gradients of variables (e.g., temperature, elevation). Color is an extremely important aspect of data visualizations as not only can it serve to focus attention on differences or particular features of a plot, it can serve to distract, overwhelm, or even disgust if it’s not used in a careful and considered manner. R and it’s package ecosystem have thousands of pre-built color palettes that can be used and that adhere to basic color theory and are accessible for those with color blindness.

Overall, we have two different ways to define color scales for our data:

  • Continuous color scales: Color gradients are often used to show the height of a 2d surface or for variables that are continuous in nature (i.e., numerical information that can take on any value within a given range or interval).
  • Discrete (i.e., categorical) color scales: Discrete color scales encode information about categorical data (i.e., a type of quantitative numerical data that can only take on specific, distinct, and countable values).

Regardless of the color scale type, we use the same basic add-on functions in ggplot to define the scale we want to use, including scale_fill_*() and scale_color_*().

  • scale_fill_*(): Modifies the interior fill color of 2D/area geoms (such as bars, polygons, tiles, violins, and density fills).
  • scale_color_*(): Modifies the stroke/border color or the color of points, lines, and text.

There are MANY different types of color scales in ggplot and we won’t go through every one. I also recommend checking out the paletteer package which gathers basically every pre-built palette that exists on the internet.

I’ve created a non-exhaustive list below and a quick reference guide for choosing the a color scale. All of these examples use fill scales, but the same exact options exist for color scales, as well.

Use these when fill/color is mapped to a factor or categorical variable (e.g., species, habitat type, treatment).

Labeling scales

We can use the labs() function to add labels to our various plot elements including the title, subtitle, caption, plot tag, x and y axes, and the names of any legend elements that are derived from aesthetics such as fill, color, alpha, size, shape, or linetype.

ggplot(mpg, aes(x = displ, y = hwy, color = class, size = cyl)) +
  geom_point() +
  labs(
    # Core Plot Text
    title = "Engine Displacement vs. Highway MPG",
    subtitle = "Data from 1999 to 2008 for popular car models",
    caption = "Source: EPA (fueleconomy.gov)",
    tag = "Fig. 1",
    alt = "Scatter plot showing that larger engines have lower highway fuel efficiency.",

    # Axis Text
    x = "Engine Displacement (Liters)",
    y = "Highway Miles per Gallon",

    # Legend Text (matches aes mappings)
    color = "Vehicle Category",
    size = "Number of Cylinders"
  )


Facets

Often, we are plotting multiple groups of data (e.g., categorical variables) that overlap one-another, and this may make it hard to decipher patterns or other characteristics about our data. For example, imagine we are plotting the daily temperature pattern across several different habitat types:

ggplot(
  data = temperature_summary,
  aes(
    x = hour,
    y = mean_temperature,
    color = habitat_type,
    group = habitat_type
  )
) +
  geom_line(linewidth = 1.2) +
  geom_point(size = 2) +
  scale_color_brewer(palette = "Dark2") +
  scale_x_continuous(breaks = seq(0, 24, 4)) +
  labs(
    title = "Daily Temperature Patterns Across Habitats",
    x = "Hour of Day",
    y = "Mean Temperature (°C)",
    color = "Habitat Type"
  ) +
  theme_minimal(base_size = 13) +
  theme(
    plot.title = element_text(face = "bold"),
    legend.position = "bottom",
    panel.grid.minor = element_blank()
  )

This plot probably works, and allows us to easily compare the differences in temperature across our different habitat types. But, it may be easier to see the patterns of individual sites, or even to compare them sometimes, by giving each habitat it’s own plot. Now, we could filter our data by habitat and create 5 different plots, but this is easily accomplished by faceting our plot:

ggplot(
  data = temperature_summary,
  aes(
    x = hour,
    y = mean_temperature,
    color = habitat_type
  )
) +
  geom_line(linewidth = 1.2) +
  geom_point(size = 2) +
  facet_wrap(~ habitat_type, ncol = 2) +
  scale_color_brewer(palette = "Dark2") +
  scale_x_continuous(breaks = seq(0, 24, 6)) +
  labs(
    title = "Daily Temperature Patterns Across Habitats",
    x = "Hour of Day",
    y = "Mean Temperature (°C)"
  ) +
  theme_minimal(base_size = 13) +
  theme(
    plot.title = element_text(face = "bold"),
    legend.position = "none",
    panel.grid.minor = element_blank(),
    strip.text = element_text(face = "bold")
  )

Facets give each sub-group (in our case, habitat type) its own sub-plot. This can be helpful if we have too many groups to visualize in one plot, or if our groups have very different y- or x-axis scales, in which case we can change facet to allow the x/y scales to vary across each sub-plot:

ggplot(
  data = temperature_summary,
  aes(
    x = hour,
    y = mean_temperature,
    color = habitat_type
  )
) +
  geom_line(linewidth = 1.2) +
  geom_point(size = 2) +
  facet_wrap(~ habitat_type, ncol = 2, scales = "free") +
  scale_color_brewer(palette = "Dark2") +
  scale_x_continuous(breaks = seq(0, 24, 6)) +
  labs(
    title = "Daily Temperature Patterns Across Habitats",
    x = "Hour of Day",
    y = "Mean Temperature (°C)"
  ) +
  theme_minimal(base_size = 13) +
  theme(
    plot.title = element_text(face = "bold"),
    legend.position = "none",
    panel.grid.minor = element_blank(),
    strip.text = element_text(face = "bold")
  )
Tip

We can adjust the scaling of our facet axes in 4 different ways:

  • scales = "fixed": x and y scales are fixed across all panels (default).
  • scales = "free_x": the x scale is free, and the y scale is fixed.
  • scales = "free_y“: the y scale is free, and the x scale is fixed.
  • scales = "free“: x and y scales vary across panels.
Note

Our faceting variables must be discrete, that is categorical. If we want to facet over a continuous variable, we must first discretize it (i.e., bin the variable). For this, we can use mutate() along with cut_interval(), cut_width(), or cut_number() to create categories.

How exactly we specify our faceting options depends on the objective of our plot and the nature of the underlying data. Sometimes it is indeed best to keep everything plotted on the same panel to ease comparisons.

Coordinates

When we’re plotting standard cartesian data (that is, X-Y data), ggplot’s default coordinate system takes care of us. There are many other coordinate systems in ggplot, and this is probably the most complicated part of plotting data. We’ll discuss a few other coordinate systems next week when we talk through making maps in ggplot. For now, there are a couple other coord*() functions that may be helpful”

  • coord_flip(): Flips the x- and y-axes. Useful for horizontal bar charts and boxplots
  • coord_fixed(): Fixes the aspect ratio between x and y units. Useful for scatterplots and spatial data
  • coord_equal(): Sets equal scaling for x and y axes (equivalent to coord_fixed(ratio = 1). Useful for spatial plots and geometric comparisons
  • coord_polar(): Converts Cartesian coordinates into polar coordinates. Useful for pie charts and circular visualizations
